# GHL-MAS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Construir um experimento reproduzível que compare três geradores de casos de teste, com dados locais, avaliação semântica e revisão humana.

**Architecture:** Adaptadores normalizam fontes locais em unidades independentes e separam requisitos de gabaritos. Soluções Pydantic AI compartilham contratos; uma pipeline determinística persiste geração, avaliação, consumo e histórico de revisão.

**Tech Stack:** Python 3.11+, Pydantic 2, Pydantic AI, Google Gemini, pytest, scipy e numpy.

**Spec:** `docs/superpowers/specs/2026-11-08-ghl-mas-design.md`; consultar também o pedido original, que contém detalhes de aceitação.

## Global Constraints

- Modelos: `gemini-3.5-flash-lite`, `gemini-3.8-flash`; embeddings: `gemini-embedding-2`.
- Cosseno bruto >= 0.70; três tentativas independentes por rodada; fuso `America/Recife`.
- Cada geração recebe todos os requisitos da unidade; gabarito nunca chega aos agentes.
- Firefox pai é somente arquivo; gerar por uma das 15 features aprovadas.
- Credenciais fora do repositório; uso indisponível não equivale a zero.
- Não executar código ou testes dos datasets; não incluir Bluetooth.

## Review Focus

- CSV com texto multilinha e BOM preserva conteúdo e não desloca linhas (Tarefa 2).
- Anotação E2EDev com lista vazia mantém requisito e contagem zero (Tarefas 3–4).
- Uso ausente em uma chamada torna total incompleto, sem mascará-lo como zero (Tarefa 5).
- Vetores inválidos ou de norma zero produzem erro de avaliação explícito (Tarefa 8).
- Interrupção durante revisão humana preserva bytes do resultado anterior (Tarefa 10).

## Estrutura de arquivos

- `schemas.py`: contratos, validação e serialização.
- `datasets/firefox.py`, `datasets/e2edev.py`, `datasets/profile.py`: fontes e perfil.
- `model_runtime.py`: modelos, estimativa de contexto e uso.
- `solutions/one_shot.py`, `solutions/ghl.py`: estratégias de referência.
- `solutions/multiagent/{agents,orchestrator,selection,state}.py`: pipeline e auditoria.
- `evaluation/{embeddings,matching,metrics}.py`: cache e avaliação.
- `persistence.py`, `main.py`, `human_review.py`: artefatos e CLIs.
- `tests/`: testes isolados com fixtures e modelos falsos; `data/` e `results/` guardam dados locais.

Cada tarefa inclui testes antes da implementação. Como o diretório ainda não é repositório Git, inicialização ou commits dependem de o usuário configurar Git; não criar repositório silenciosamente. Se houver Git na execução, registrar cada tarefa com commit após testes.
